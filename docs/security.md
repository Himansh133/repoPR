# Security

Safety controls and the tests that cover them. One line per control.

- Secrets live only in `.env`, which is git-ignored. `.env.example` has placeholders. (Chunk 0)
- Tests that call the network or a real LLM are skipped by default (`live`, `docker` markers). (Chunk 0)
- API key and GitHub token are `SecretStr`; tests check they do not appear in `repr` or error messages. (Chunk 1)
- LLM calls are bounded: timeout, max 3 retries, max output tokens 4,000. 401/403 is never retried. (Chunk 1)
- Default tests mock all HTTP with `respx`; real calls only under `-m live`. (Chunk 1)
- All file access goes through `Workspace.resolve`: rejects absolute paths, `..`, null bytes, and symlink escapes (file and directory). Tested. (Chunk 2A)
- File reads are size-bounded; binary files are refused; errors never contain absolute paths. (Chunk 2A)
- Clone allows only `https://github.com/<owner>/<repo>`, uses a fixed argument list with `--`, no shell, with a timeout. (Chunk 2A)
- GitHub client is read-only, validates owner/repo/number before any request, caps issue and comment size, rejects pull requests, and never logs the token. Tested. (Chunk 2B)
- `search_code` runs ripgrep with a fixed argument list and no shell; flag-like queries are plain text; query, match, snippet and time limits; symlinks not followed. Tested with both backends. (Chunk 2C)
- Prompt-injection text in fixture files is returned as plain data and never acted on. Tested. (Chunk 2C)
- Dispatcher allowlists tools, caps argument size (4 KB), rejects non-JSON-object, missing, extra and wrongly typed arguments, limits distinct files read (10) and result size. Errors go back to the model and never raise. Tested. (Chunk 3A)
- Tool output is wrapped in `<untrusted_repo_content>`, and tags inside file text are escaped so a file cannot break out. Tested. (Chunk 3A)
- Plans are accepted only if every cited file was actually read (checked by the backend, not the prompt). Tested. (Chunk 3B)
- The loop is finite: step limit, token budget, timeout, abort after 3 invalid calls in a row. Tested. (Chunk 3B)
- Issue text is wrapped as untrusted and cannot close its wrapper; a model that follows injected instructions (asks for a shell tool) is refused by the dispatcher and the run continues. Tested. (Chunk 3B)
- Events store names, counts and sizes only, never file contents or model text. Tested. (Chunk 3B)
- Patches are parsed strictly: size and file limits; no deletes, renames, mode changes or binary patches; no `..`, absolute, backslash, `.git` or `.github` paths; no symlink paths. Tested. (Chunk 4A)
- Patches are applied only in a temp clone, never in the user's checkout; git hooks are disabled and a planted hook does not run. Tested. (Chunk 4A)
- Sandbox: fixed profiles only (no model commands, no shell); no network, non-root, read-only root and mount, dropped capabilities, memory/CPU/process/time limits; timeouts force-remove the container; logs are bounded in memory and in the result. Tested with a mocked Docker layer and with a real container. (Chunk 4B)
- Python repos with a `requirements.txt`: wheels only (`pip install --only-binary=:all:`, no package code runs), from plain requirement lines only (options, paths, URLs and direct references are refused), into a folder outside the repo that the offline test run sees read-only and that is deleted after the run. The install container has network, a read-only repo mount and the usual limits. Tested with a mocked Docker layer and a real container.
- Node repos: dependencies are installed once by a fixed `npm ci --ignore-scripts` (no package scripts run) from the committed `package-lock.json`, in a separate locked-down container that has network. The tests then run offline with the repo mounted read-only, like the Python profile. The model cannot choose the profile or the install command. Tested with a mocked Docker layer and checked by hand against a real container.
- Timeout, out-of-memory and sandbox errors are `violation`, which aborts the run. (Chunk 4B)
- The model cannot run tests or commands; the backend runs the fixed profile after each patch. `run_tests` and `run_shell` requests are refused. Tested. (Chunk 4C)
- A run is `passed` only if tests failed before the patch and pass after it; no tests, or already passing, is `inconclusive`. Tested. (Chunk 4C)
- Sandbox violation, timeout or sandbox error aborts the run immediately. Tested. (Chunk 4C)
- Repair feedback is only failed test names and 3,000 characters of output, wrapped as untrusted; events never contain diffs or test logs. Tested. (Chunk 4C)
- Max 2 repair attempts; step, token and time budgets apply to the whole run. Tested. (Chunk 4C)
- The database file is private (0600). Test logs and file contents are never stored; patch diffs are, bounded to 20 KB. Tested. (Chunk 5A)
- Daily run limit (5) and daily spend cap block new runs; runs that crash still count; unpriced runs are blocked unless explicitly allowed. Tested. (Chunk 5A)
- CLI: daily limits are checked before any clone, GitHub call or model call; only `https://github.com/<owner>/<repo>` URLs are cloned; secrets never appear in output; a crash is recorded, not hidden. Tested. (Chunk 5B)
- Eval: benchmark entries are validated (ids, dir: paths must stay inside the project, GitHub URLs only with a hex commit fetched by fixed git commands); `--max-runs` guards against accidental large runs; the daily spend cap applies and stops remaining runs; the benchmark hash is saved with the results. Tested. (Chunk 5C)
- Draft PR: only after typing `yes` (or `--yes`); only `passed` runs; never after a rejection; one PR per run; never merges, force-pushes or overwrites a branch; only `repopilot/` branches; the PR holds exactly the tested working copy (HEAD and clean tree checked); separate least-privilege `GITHUB_WRITE_TOKEN` sent only in the Authorization header, never to git; the new branch is deleted if the PR fails; the token never appears in output. Tested with mocked GitHub. (Chunk 7)
- API: every endpoint except `/health` needs `X-API-Key` (constant-time compare; the server will not start without a key of 16+ characters); binds to 127.0.0.1 by default and warns otherwise; strict request schemas (unknown fields and oversized text rejected); write endpoints rate limited; one run at a time; approve needs `confirm: true`; responses never contain secrets or the working-copy path. Tested, including a mutation check that disables auth. (Chunk 8)
- Dashboard: the key is checked against the API, stored only in `sessionStorage`, sent only as a header to same-origin paths, and cleared on any 401; server text (titles, diffs, reports, events) is rendered as text, never HTML; approve needs a second explicit click and sends `confirm: true` only then. Tested. (Chunk 8B)
